# Luka Poropat — personal website

Live at <https://lukaporopat.github.io>. Static site for GitHub Pages (no build step), styled after
[ia-chow.github.io](https://ia-chow.github.io/).

| Page | What's on it |
|---|---|
| `index.html` | Bio and links |
| `research.html` | Planetary defence (NEO follow-up), solar physics & daytime seeing, robotic observatory software |
| `observations.html` | World rank, **3D map of every object observed**, statistics, object table |
| `publications.html` | MPECs crediting me (searchable), link to NASA ADS |
| `gallery.html` | AstroBin images with a lightbox |
| `faq.html` | Copyright & usage FAQ (all rights reserved) |

## Things to update by hand

- **Images:** the research figures live in `assets/images/research/` (`solar.jpg`, `robotic*.jpg`); replace a
  file to change its picture.
- **Headshot:** replace `assets/images/headshot.jpg` (portrait, about 4:5) to update it.
- **CV:** taken off the site for now (October 2026). To bring it back, add `cv/Luka_Poropat_CV.pdf` again and
  restore the "CV" links in the menu, under the bio and in the footer (see the Git history).

## Themes

The NASA-coloured theme (NASA blue #0B3D91 and red #FC3D21) is the native one for every visitor; the
button in the top-right corner switches to dark (remembered per browser). All colours are tokens in
`assets/css/main.css`. The earlier navy look and a "logbook" alternative can be previewed by adding
`?theme=light` or `?theme=logbook` to any URL. Only NASA's colours are used, never the NASA insignia.

## Data

Everything in `data/` is generated by the scripts in `tools/` (Python 3, standard library;
the gallery script also needs Pillow):

```bash
python tools/build_observations.py          # MPECs crediting me + JPL orbits -> data/observations.json
python tools/observer_rank.py               # world rank from MPEC Watch      -> data/rank.json
python tools/fetch_astrobin.py              # AstroBin images                 -> data/gallery.json
```

- `build_observations.py` reads the list of Višnjan (L01) circulars from
  [MPEC Watch](https://sbnmpc.astro.umd.edu/mpecwatch/byStation/station_L01.html) and the list of my
  circulars from [Jost Jahn's MPEC statistics](https://mpec.jostjahn.de/) (MPEC Watch misses some, and
  lists new ones later), downloads each MPEC from the Minor Planet Center once (cached in `tools/.cache/`),
  keeps those whose observer details name me, extracts the objects from the L01 observation lines and
  fetches their orbits from the [JPL Small-Body Database API](https://ssd-api.jpl.nasa.gov/doc/sbdb.html).
  Circulars only Jost Jahn lists get their "first follow-up" flag and object type worked out from the
  MPEC itself, the way MPEC Watch does. If his list can't be read, the run uses MPEC Watch alone.
  `data/mpec_index.json` remembers every circular already checked, so later runs are quick.
  Orbits are cached as well and re-fetched from JPL once they are a month old.
- `observer_rank.py` sums MPEC Watch's per-observatory "Individual Observer" tables over all
  observatories with at least 150 MPECs and ranks every individual. If MPEC Watch can't be read
  completely, it leaves the previous `data/rank.json` untouched.

The workflow in `.github/workflows/update-data.yml` looks for new MPECs every day (05:17 UTC) and also
runs the rank and gallery scripts on Mondays; when anything changed it commits the new data and publishes
the site, so the statistics, the 3D map and the rank stay current on their own. It also publishes the site after every push to `main`, and you can start it by hand from the
*Actions* tab (*Update data and publish → Run workflow*).

## Languages

English is the default. Every page has a Croatian copy in `hr/` with the same file name, and the "HR" /
"EN" button next to the theme switch opens the same page (and section) in the other language. Croatian
pages start with `<html lang="hr" data-root="../">`: the scripts read `lang` for their wording, number
formats (1.125; 0,42 AJ) and Croatian plural forms, and `data-root` to find `assets/` and `data/`, so both
languages share one copy of the scripts, styles, images and data. Each page links its other-language twin
(`hreflang`), and the sitemap lists both.

When you change the text of an English page, make the same change in its `hr/` twin.

## Security

- Every page carries a Content-Security-Policy (`<meta http-equiv="Content-Security-Policy">`): scripts may
  only come from this site and inline scripts are blocked, so keep JavaScript in `assets/js/` files. Adding
  a new outside source (a font, a stylesheet) means adding its origin to the policy on every page.
- Three.js (r170) is self-hosted in `assets/vendor/three/`, taken from the npm package (checksum-verified),
  so no third-party server can change the code that runs on the site. The Font Awesome stylesheet is pinned
  with a Subresource Integrity hash; Bootstrap's already was.
- Links read from the data files are only used if they are `https://`.
- The workflow runs with read-only permissions; only its commit step gets a write token, and the download
  scripts never see it. The repository only allows GitHub's own actions, and `main` can't be force-pushed
  or deleted.

## Preview locally

```bash
python tools/serve.py
```

then open <http://localhost:8765>. (Opening the HTML files directly won't load the data.) The server tells
the browser to re-check every file on each load, so a normal reload always shows your latest edits.

## Publish

1. Create an empty GitHub repository named `<your-username>.github.io`.
2. In its *Settings → Pages → Build and deployment*, set *Source* to **GitHub Actions**.
3. Leave *Settings → Actions → General → Workflow permissions* at the default (*Read*): the workflow
   asks for exactly what each job needs (only its final commit step can write).
4. Push this folder to the `main` branch. The push publishes the site at
   `https://<your-username>.github.io`; from then on it refreshes itself every day.
   (If you pushed before step 2, re-run the workflow from the *Actions* tab.)
